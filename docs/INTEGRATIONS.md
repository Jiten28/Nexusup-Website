# External integrations and activation

No paid service, scheduler, production database or external account has been activated. Public provider smoke tests are read-only. Never place private keys in templates, JavaScript, URLs shared with readers or version control. The app reads exported environment variables; it does not auto-load .env.

## News ingestion — RSS/Atom first

1. Back up the real target database in staging. Install requirements, inspect/apply the additive `0002` migration. Do not replace an existing database with the bundled demo.sqlite3.
2. Run `python manage.py configure_sources`. Idempotently adds missing India, World, Politics, Sports, Entertainment and Health and Lifestyle categories plus two **disabled candidate** BBC RSS sources. Existing Cricket, Business, Stock Market, Investments, Technology and Science remain.
3. In `/admin/news/newssource/`, supply a publisher-authorized public HTTPS feed and review current reuse terms. Record its terms URL/reuse notes. Set a default category and optional JSON category map (e.g. `{"technology":"technology","business":"business"}`). Map keys should match lowercased provider category names. Do not treat publicly accessible XML as a blanket republication or image license.
4. Explicitly confirm reuse rights, then enable the source. Defaults: editorial draft review, no remote images, 30-minute source interval. To use publisher images, separately confirm permission, enable images and list exact approved image hostnames (e.g. `["images.publisher.example"]`). No article pages or full article bodies are fetched. Imported metadata comprises title, excerpt (max 360 characters), source, URL, publication time if supplied, import time/category and permitted remote image URL. Missing feed publication times remain visibly unspecified; local publication time is used for scheduling only.
5. Export `NEWS_FETCH_ENABLED=1`, test `python manage.py fetch_news --source <id> --dry-run`, then `python manage.py fetch_news --source <id>`. Dry-run downloads/parses XML but does not save articles, status or fetch logs. It respects the existing next-fetch time.
6. Install/adapt `deploy/news-fetch.cron.example` on the deployment server, with a least-privilege service account and private environment file. **No cron job is installed by this deliverable.** Five-minute polling is bounded by each source's next-fetch timestamp (minimum five-minute interval). Use one job/DB; `flock` avoids overlapping jobs. Fetch command returns nonzero if any eligible source fails. Monitor failures and log rotation.
7. Review drafts and publish in the existing Article admin. To change the homepage center, select ONE currently published article and run **Make ONE selected published article the central featured story**. New imports always have `featured=False`; they do not replace an existing featured choice. The old featured checkbox remains compatible; if several are checked, most recent published wins. If none is selected, the latest public article is the fallback.

Dedup uses SHA-256 of normalized story URL, stripping fragments, tracking parameters and sorting query parameters; duplicate feed URLs are skipped, not overwritten. URL normalization currently upgrades HTTP article URLs to HTTPS. Sites without HTTPS need an adapter change. Equivalent articles with genuinely different URLs are not semantically deduplicated. Feed entries are capped at 100 per run; very high-volume feeds need cursor/backfill work. Multiple feeds can share a canonical URL and dedup across sources. Manual stories without an import hash are never overwritten and are not dedup-matched automatically.

Transport: verified TLS, public-IP pinning at connect time, redirect revalidation, no inherited proxy, 8-second socket timeout, 2 MB response limit, and entity-safe XML preparse. Use outbound firewall/allowlists in production as defense in depth; DNS/system resolver timing, shared provider quotas, parallel workload limits and complete security certification remain deployment concerns. Failure retains all stored content; next interval permits retry. Source status and immutable-in-admin FetchRun records show attempts, errors, imports and skips. No homepage network ingestion.

`ADAPTERS` in `news/ingestion.py` accepts application-controlled adapter classes returning the same metadata dictionary as RSSAdapter. There is no paid news API provider adapter or secret configured yet. A future API adapter must implement the provider's authorization, pagination, quotas and image/republication terms; register it in server code, never executable admin text. BBC India/World are configuration candidates only; additional category/India-first providers require editorial/rights selection. Coverage is not magically populated by adding a category.

## Widgets

All six tools open from header Widgets; weather also opens from the location button. Calculator (safe arithmetic parser), units (length, weight, volume, temperature), world clock and calendar work offline. World clock uses device time/IANA zones including DST; it is not a clock synchronization service. Currency/weather return explicit unavailable states by default.

Export `UTILITIES_NETWORK_ENABLED=1` only after provider review:
- **Currency:** [Frankfurter v2](https://frankfurter.dev/), daily blended reference rate (not live trading). No API key. Its documentation permits commercial use of blended rates; direct individual-provider endpoints have their own terms. Eight currencies exposed: INR, USD, EUR, GBP, JPY, AUD, CAD, AED. Server cache one hour; rate date displayed. No invented rates when unavailable.
- **Weather/cities:** [Open-Meteo](https://open-meteo.com/en/pricing), temperature, conditions, wind and provider observation time, ten-minute weather cache and one-day city cache. Appropriate CC BY 4.0 attribution is displayed. Free API is for evaluation/non-commercial use and rate limited. Commercial weather requires a subscription; set server-only `OPEN_METEO_API_KEY` to use `customer-api.open-meteo.com`. City lookup currently uses the public geocoding endpoint; confirm commercial geocoding eligibility/endpoint with the provider before launch. Current subscription amounts must be checked at purchase; none purchased here.
- Browser geolocation is requested **only** after **Use device location**. Denial/unavailability preserves manual city search and coordinate input; coordinates rounded to ~0.01 degrees before storage/request. City lookup requires the provider; manual coordinates bypass lookup, not the weather provider. Header local date/time uses `Intl` device time zone without geolocation. A saved location is kept locally; opening weather does not fetch until the user selects/requests a location.

Caches and session translation cooldown are process-local in the demo. Before public activation, replace with a shared cache and add IP/account-level budgets/rate limits at the application gateway, especially to protect paid translation and weather. No stale weather or fabricated rate is shown after provider failure. No global account sync of local settings.

## Translation evaluation and setup

Chosen design: a server-side API, not an unlicensed embedded Google Translate/GTranslate website widget. No Google scripts/cookies are injected. Google Cloud offers broad language coverage and billing/quota controls; exact choices come from its live supported-language endpoint rather than a fake static list.

**Google Cloud Translation Basic v2:** enable the API in an approved billing project, restrict an API key to Translation API and server usage, set budgets/quotas; export `TRANSLATION_PROVIDER=google` and `TRANSLATION_API_KEY=<private value>`. [Pricing](https://cloud.google.com/translate/pricing) is character-based per target language (NMT pricing example: $20/million input characters, subject to current tiers/credits); check current billing details before activation. Public article text is transmitted to Google. No live authenticated Google test was possible without a user-owned key/billing project.

**LibreTranslate:** export `TRANSLATION_PROVIDER=libre`, approved public-HTTPS `LIBRETRANSLATE_URL`, and `TRANSLATION_API_KEY` if required. [Docs](https://docs.libretranslate.com/) describe managed hosting with a paid API key or self-hosting. Argos model availability determines supported English language pairs; generally less coverage/quality than Google's broad service. Self-hosting has infrastructure/operations costs and open-source license obligations (review AGPL dependencies); no instance is deployed here. This hardened client intentionally rejects private-network/local HTTP endpoints; use an approved public HTTPS deployment or separately reviewed internal adapter.

Language dropdown loads only supported pairs from the configured provider. Original English is always recoverable. Marked public headlines/excerpts/article paragraphs and some navigation labels are translated by replacing text nodes only; links, images, form inputs and handlers are retained. UI is **partially localized**, not an assertion of complete site translation. About/legal/contact body copy, source names, metadata and many utility controls remain English. Homepage/list translation corpus is bounded to the latest 24 eligible stories, so older paginated/search results can remain English; article pages translate their own body. RTL language direction is supported, but professional RTL/linguistic validation is outstanding.

Translation endpoint accepts only a local public path and target language, derives its corpus on the server (not a free-text paid proxy), enforces CSRF, a 2 KB request envelope, 45k-character corpus limit, per-session cooldown and one-day result cache. Errors retain the current visible content. Google/Libre unit tests and browser translation fixtures passed; real account credentials, spend, full language-quality testing and production traffic quotas are not verified.
